How It Works
1
Forward Pass
All input features flow through each layer. Neurons compute weighted sums then apply the activation function.
2
Measure Loss
The prediction is compared to the true label. Cross-entropy loss quantifies how wrong it was.
3
Backpropagation
The error flows backwards, computing how much each weight contributed to the mistake.
4
Update Weights
Adam optimizer nudges each weight to reduce the loss. Repeat thousands of times!

📖 Glossary
Feature — A single input value (column in your CSV).
Neuron — Weighted sum of inputs + activation function.
Weight — Learnable number scaling each connection.
Loss — How wrong the model is — lower is better.
Precision — Of all predicted positives, how many are truly positive?
Recall — Of all actual positives, how many did the model catch?
F1 Score — Harmonic mean of Precision & Recall. Balanced metric.
R² Score — Variance explained by predictions. 1.0 = perfect fit.
Epoch — One complete pass over all training data.
Backprop — Computes how to improve each weight.

Convolutional Neural Networks

When you look at a photo, you don't analyse every pixel one at a time — your brain picks up edges, shapes, textures in overlapping patches and builds up meaning layer by layer. CNNs work exactly the same way. A small sliding window called a kernel scans the image, activating wherever it finds the pattern it's learned to detect. Stack enough of those layers and you get something that can recognise a face, count people in a crowd, or spot a tumour on an X-ray.

This page walks you through the mechanics, gives you a live kernel playground to experiment with, and finishes with a real project: a CNN-powered face detection attendance system.

🔲 Local filters 📦 Weight sharing 🗺 Feature maps ⬇ Pooling 👤 Face detection
Part 1 — How CNNs Work

What Makes a CNN Different?

THE CORE IDEA

A regular neural network applied to a 224×224 image would need to connect every input pixel to every neuron — that's 50,000+ connections per neuron, times millions of neurons. Completely impractical.

CNNs sidestep this with two tricks: local connectivity (each neuron only looks at a small patch) and weight sharing (the same filter is applied across the entire image). A single edge-detection filter learned in one corner works everywhere.

Dense network
50k params/neuron
❌ Intractable
CNN with 3×3 filter
9 params/filter
✓ Scales to any size

Layer by Layer

FROM PIXELS TO PREDICTION
🔲
Conv Layer
Slides a filter across the image computing dot products. Each filter detects one pattern type — horizontal edges, curves, colour gradients.
⚡
ReLU Activation
Sets all negative values to zero. Adds non-linearity so the network learns complex shapes, not just linear combinations.
⬇
Max Pooling
Takes the max in each 2×2 block. Halves spatial size, keeps strong activations, makes the network robust to small shifts.
🧠
FC + Softmax
Flattened features fed through a dense network for final classification. Softmax outputs one probability per class.

Famous Architectures

30 YEARS OF PROGRESS IN FOUR MODELS
LeNet-5 (1998)
2 conv layers. Handwritten digit recognition. The proof that convolutions work.
AlexNet (2012)
Won ImageNet by 10%. ReLU + dropout + GPU. Triggered the whole deep learning wave.
VGGNet (2014)
19 layers of tiny 3×3 kernels. Going deeper always helps. Still used as a backbone today.
ResNet (2015)
152 layers with skip connections. Solved vanishing gradients for good. The standard backbone today.

Instead of someone calling out names, a camera above the classroom scans the room, a CNN detects every face, and the system compares each one against a registered student database. Attendance is marked automatically in seconds. Used in universities and offices worldwide.

The embedding is compared against all registered student embeddings using cosine similarity. If above a threshold, it's a match.
sim(emb, db[i]) > 0.85
→ "Student Name ✓"
4
Mark Attendance
Matched IDs are written to the log with a timestamp. Unknown faces are flagged. Count of present vs total is reported.

# Step 1: Detect faces with MTCNN
from mtcnn import MTCNN
import cv2

detector = MTCNN()
img = cv2.imread('classroom.jpg')
faces = detector.detect_faces(img)
print(f"Detected {len(faces)} faces")
# Step 2: Get embeddings with FaceNet
from deepface import DeepFace
import numpy as np

def get_embedding(face_img):
    emb = DeepFace.represent(
        face_img, model_name='Facenet')
    return np.array(emb[0]['embedding'])
# Step 3: Match against student DB
from sklearn.metrics.pairwise import (
    cosine_similarity)

def identify(emb, student_db, thresh=0.85):
    for s in student_db:
        sim = cosine_similarity(
            [emb], [s['emb']])[0][0]
        if sim > thresh: return s['name']
    return "Unknown"
# Step 4: Write attendance log
import csv, datetime

def mark_attendance(name):
    with open('attendance.csv','a') as f:
        writer = csv.writer(f)
        writer.writerow([
            name,
            datetime.datetime.now()
                .strftime('%Y-%m-%d %H:%M:%S'),
            'PRESENT'
        ])

Challenges & Ethics

THE THINGS TEXTBOOKS SKIP OVER
⚠️ Bias in Training Data
Early face recognition models had 34% error on dark-skinned women vs 0.8% on light-skinned men — because training data was mostly white male faces.
🌡 Lighting & Occlusion
CNNs degrade with harsh shadows, masks, or extreme head angles. Data augmentation during training helps — but never fully solves it.
✓ Threshold Tuning
Too high a similarity threshold = false rejections. Too low = false approvals. The right value depends on the cost of each type of error.
🔒 Privacy & GDPR
Face embeddings are biometric data. GDPR treats them as sensitive personal information — you need consent, encryption, and a deletion mechanism.

Recurrent Neural Networks & LSTM

Regular neural networks are stateless — they look at one input, produce one output, and forget everything. But most interesting problems in the real world involve sequences — words in a sentence, frames in a video, notes in a melody. That's where RNNs come in. They have a memory that carries context from step to step.

This page walks you through how they work, why they struggled, how LSTM fixed that, and how the same idea powers the chat reply bot you can interact with below.

📖 Sequential data 🧠 Memory across time 🔁 Shared weights 💬 Powers early chatbots 🎵 Music & speech
Part 1 — Understanding RNNs

What is an RNN?

THE CORE IDEA

Imagine reading the sentence "The cat sat on the..." — by the time you hit "the", your brain already knows a noun is coming, because you remember every word before it. A plain neural network can't do that. It sees each word in isolation.

An RNN adds a loop: after processing each token it saves a hidden state h — a small vector summarising everything it's seen so far. That hidden state gets passed forward to the next step along with the next input. Same weights, reused at every step.

h(t) = tanh( Wxh·x(t) + Whh·h(t−1) + b )
y(t) = Why·h(t)

The key insight: the same weight matrices W are used at every timestep. The network shares what it learns across the whole sequence.

RNN Unrolled Through Time

SAME WEIGHTS · DIFFERENT TIMESTEPS

Unrolling means "stretching out" the loop so you can see every step separately. It's the same cell applied repeatedly — the purple arrows carry memory forward.

🟣 Purple = hidden state h flowing through time  |  🟢 Green = output at each step

The Vanishing Gradient Problem

WHY VANILLA RNNs CAN'T REMEMBER MUCH

Here's the painful truth about plain RNNs: they're terrible at remembering things from more than ~20 steps ago. And it's a mathematical inevitability, not a bug you can fix by tweaking hyperparameters.

During backpropagation through time (BPTT), gradients are multiplied at every step by the same weight matrix. If those values are even slightly less than 1, the gradient exponentially shrinks as it travels backwards. By the time it reaches step 1, it's practically zero — the early tokens get almost no feedback.

A concrete example:
gradient × 0.95 = 0.59   (still OK)
gradient × 0.920 = 0.12   (almost nothing)
gradient × 0.950 = 0.005   (gone)

This is why early chatbots using vanilla RNNs would start contradicting themselves after a few sentences — the model literally forgot what it said earlier.

LSTM — Long Short-Term Memory

THE FIX THAT CHANGED EVERYTHING

LSTM (Hochreiter & Schmidhuber, 1997) solved vanishing gradients by adding a second kind of state: the cell state c — a highway that lets gradients flow backward with minimal modification. Three gates control what flows through it:

🗑
Forget Gate
Looks at h(t−1) and x(t), outputs a number between 0 and 1 for each cell state value. 0 = "erase this completely", 1 = "keep this perfectly".
📥
Input Gate
Decides which new values to write into the cell state. Works alongside a tanh layer that creates candidate values to potentially add.
📤
Output Gate
Filters the cell state through tanh and decides what portion to expose as the new hidden state h(t) — what the next step actually "sees".
The cell state flows almost unchanged through time — gradients can flow back through it without vanishing. That's the key innovation.

Chat Reply Bot — Full Project Walkthrough

HOW AN LSTM LEARNS TO HOLD A CONVERSATION · CONCEPT + SIMULATION

This is the core idea behind every chatbot — from early Siri to pre-Transformer assistants. An LSTM reads your message word-by-word into a compressed memory called the context vector, then a decoder LSTM generates a reply one token at a time. Modern LLMs like GPT-4 scale this same idea to billions of parameters.

HOW THE CHATBOT WORKS — 4 STAGES
1
Tokenise
Split the input into tokens (words). Each token is looked up in a vocabulary and converted to an integer ID.
"hi how are you"
→ [42, 17, 8, 91]
2
Encode
The Encoder LSTM reads each token, updating its hidden state h and cell state c. After the last token, the final h is the context vector.
x₁→LSTM→x₂→LSTM
→x₃→LSTM → h_enc
3
Decode
The Decoder LSTM starts from h_enc and generates one token at a time. The Softmax produces a probability over the full vocabulary.
h_enc → "I" → "am"
→ "fine" → <END>
4
Train
For each decoded token, cross-entropy loss compares prediction vs ground truth. BPTT updates all encoder + decoder weights backward through all steps.
Loss=-log P(correct)
Grad flows backward

📚 How the LSTM Chatbot Was Trained
📄 Training Data
Millions of (question, answer) pairs scraped from conversations, FAQs, and dialogues. Each pair becomes a training example:

"how are you" → "I am fine thanks"
⚙️ Teacher Forcing
During training, the decoder receives the ground truth previous token (not its own prediction). This speeds up training. At test time it uses its own outputs — the "autoregressive" mode you see in the simulation.
📉 Loss Function
Cross-entropy at each decoder step: L = −log P(correct word)

The total loss is summed across all positions. BPTT propagates it back through both decoder and encoder simultaneously.
🌡 Inference: Sampling
At inference the softmax output is a probability distribution. Temperature T scales it: T→0 = always pick top token (safe), T→∞ = uniform random (chaotic). The slider in the simulation controls this!
Part 3 — Beyond LSTMs

Things That Make Chat Models Tick

KEY CONCEPTS FROM LSTM CHATBOTS TO CHATGPT
🗂
Vocabulary & Tokenisation
Every word gets mapped to an integer ID. GPT-4 uses roughly 100k unique tokens. At each decoder step the model outputs a probability over that entire vocabulary — the one with the highest probability (or a sampled one) becomes the next word.
🌡
Temperature & Sampling
Temperature is just a number you divide the softmax logits by before sampling. Low temperature (0.1) → always picks the safest word, replies sound robotic. High temperature (1.5) → picks surprising words, replies sound creative but can get weird. The slider in the chat above controls this.
🔍
The Attention Breakthrough
In 2015, Bahdanau et al. added attention to the LSTM decoder: instead of relying on one context vector, the decoder could look back at all encoder states and weight them dynamically. This was the direct precursor to the Transformer — and ultimately to ChatGPT.

RNN → LSTM → Transformer

A 30-YEAR JOURNEY IN THREE STEPS

Each architecture solved the problems of the one before it. Here's how they stack up:

⚙️ Vanilla RNN (1980s)
✓ Simple, fast  ✗ Vanishing gradients  ✗ Forgets after ~20 steps. Fine for very short sequences, terrible for anything real.
🧠 LSTM (1997–2017)
✓ Long-term memory  ✓ Handles 100s of steps  ✗ Sequential — can't parallelise training. Powered chatbots, translation, and speech for 20 years.
✨ Transformer (2017–now)
✓ Attention over all positions at once  ✓ Fully parallelisable  ✓ Scales to trillions of tokens. GPT-4, Gemini, Claude — all Transformers.
